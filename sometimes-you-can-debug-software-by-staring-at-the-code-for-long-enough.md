# Sometimes you can debug software by staring at the code for long enough

↑ **Parent:** [Ciro Santilli's software engineering wisdom](ciro-santilli-s-software-engineering-wisdom.md)  
ⓦ [Wiki](https://en.wikipedia.org/wiki/Sometimes_you_can_debug_software_by_staring_at_the_code_for_long_enough)

Once upon a time, when [Ciro Santilli](ciro-santilli-split.md) had a job, he had a programming problem.

A senior developer came over, and rather than trying to run and modify the code like an idiot, which is what [Ciro Santilli](ciro-santilli-split.md) usually does (see also experimentalism remarks at [Section "Ciro Santilli's bad old event memory"](ciro-santilli-s-bad-old-event-memory.md)), he just stared at the code for about 10 minutes.

We knew that the problem was likely in a particular function, but it was really hard to see why things were going wrong.

After the 10 minutes of examining every line in minute detail, he said:

> I think this function call has such or such weird edge case

and truly, that was the cause.

And so, [Ciro was enlightened](the-correlation-between-software-engineers-and-buddhism.md).
